原则 1 骨架复用：ReAct 全系统只有一份

「一次对话回合的骨架」全部抽到 BaseAgentRuntime（app/agent/base.py）： MedicalAgent 与 MultiAgentOrchestrator 只负责各自的中间段 （路由 + 委托子Agent），提取/降级/压缩/会话骨架零复制。 反面对照：同类项目把约 200 行代码复制粘贴两处，改一处漏一处。

原则 2 tracer 是一等公民

Tracer 以依赖注入的方式进入 LLMClient 与 ToolRegistry， 运行时就能看 token 成本与延迟；评估沙箱直接读 tracer（零 monkey-patch、零全局状态）。 事件类型：llm_call / tool_call / route / redflag_shortcut / injection_blocked / fake_citations_removed。

原则 3 Settings 可多实例

评估沙箱用 Settings(memory_enabled=False, mock_mode=True) 构造独立配置，不改全局单例 → 无状态泄漏。 mock_mode 显式化：MOCK_MODE=1 或未配 API Key 自动进离线模式， MockLLMClient 与真实客户端同接口、会读对话历史——离线轨迹与真实模式结构一致。

原则 4 确定性优先的医疗安全

急症红线规则短路、危急值按字段升级、参考来源由代码生成—— 安全攸关的判断走确定性代码而非模型自由发挥。 会话持久化先写 .tmp 再 os.replace 原子替换， 崩溃不留半截文件；load_session() 对损坏/版本不符返回 None 视为新会话。

本轮为什么是这 2 次 LLM 调用

第 1 次 react · 输入 system+user+tools(9件套) → 输出 tool_calls: query_lab_report(LAB-2026-004)
第 2 次 react · 输入 追加 assistant(tool_calls)+tool观察 → 输出 final 纯文本（62 token），循环结束
（extract 提取在 mock 模式直接查表构造，不计 llm_call； 真实模式为第 3 次，purpose="extract"）

工具九件套：query_appointment / cancel_appointment / query_medicine / check_drug_interaction / query_lab_report / query_department / search_knowledge / recall_user_memory / load_skill （app/agent/tools/registry.py build_tool_registry）。 registry.execute 前做必填参数与类型校验，工具抛异常打包成 {"error": ...} 观察，单工具故障不炸整轮会话。

工程要点

组合不改写 KnowledgeRetriever 只暴露 .search() 契约， 换 embedder/后端不动 search_knowledge 工具
一致性校验 索引自带 embedding 模型签名， 加载比对不一致直接报错（拒绝沉默劣化）
离线开箱跑 无 Key 自动降级 hash 向量 + 自动建索引， 全链路零成本可测
数据边界 sanitize_tool_output 包边界+剥注入行， 检索资料里的指令性文本进不了模型上下文
来源确定性 回复没带来源时代码补「参考来源」附录 （append_sources_if_missing，非模型生成）
