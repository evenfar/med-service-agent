# 第0期 · 项目骨架与配置

> 搭好一个"离线开箱即跑"的医疗导诊 Agent 骨架：配置可多实例、离线判定集中一处、可观测是一等公民。

## 本期目标

- 理解项目定位：**互联网医院"健康咨询与导诊助手"教学项目**。所有数据来自 `app/agent/tools/mock_data.py` 的模拟数据（预约单 / 药品 / 检验报告），**不做诊断、不开处方**——这条边界作为硬约束写进 `app/prompts/consultant.py`。
- 看懂目录结构：每一层分别解决什么问题，后续各期在哪个文件上叠加。
- 掌握 `Settings` 的**可多实例**设计：评估沙箱构造独立配置，不污染全局状态。
- 理解 `is_offline()` + `build_client()` 工厂：没有 API Key 也能零成本跑通全链路（`python main.py --mock`）。
- 理解 `Tracer` 作为**一等公民注入**：运行时就能看 token 与延迟，评估时零 monkey-patch。

## 核心实现讲解

### `app/config/settings.py`：可多实例的 Settings

- `Settings(BaseSettings)` 只是普通的配置类，**模块底部没有 `settings = Settings()` 这样的全局单例**。谁需要配置，谁自己构造一份：`main.py` 里 `settings = Settings()`，测试里 `Settings(mock_mode=True)`，评估沙箱 `app/evaluation/sandbox.py` 的 `_settings()` 里 `Settings(memory_enabled=False, mcp_enabled=False, mock_mode=True)`。
- 显式 kwargs 优先级高于 `.env` 与环境变量（pydantic-settings 的规则），所以沙箱能精确覆盖个别字段；`tests/test_schemas_settings.py::test_multi_instance_isolation` 直接验证两个实例互不影响。
- `model_config = {"env_file": ".env", "extra": "ignore"}`：`.env` 里存在项目未声明的变量时不会报错（参照项目 只配了 `env_file`）。
- 关键默认值都在这定：`llm_max_retries=3`、`llm_retry_base_delay=1.0`（退避 1s/2s/4s）、`max_react_steps=6`、`history_threshold=12`、`history_keep_recent=4`、`trace_path`。

### `is_offline()`：开箱即跑的判定

```python
def is_offline(settings: Settings) -> bool:
    return settings.mock_mode or not settings.openai_api_key
```

- 两种情况都算离线：显式 `MOCK_MODE=1`，或压根没配 Key（`test_defaults_offline_when_no_key`）。
- 判定**收敛在一个函数里**：`build_client()`（`app/llm/client.py`）用它切换 Mock/真实客户端，`app/agent/rag/embedder.py`、`app/agent/rag/retriever.py`、`app/evaluation/evaluator.py` 等装配点也都复用同一个 `is_offline()`，业务代码不散落各写一套 if-else。CI 没有凭据也能全量跑测试，这是"教学项目开箱即跑"的根基。

### `app/agent/tracer.py`：一等公民的可观测

- `Tracer(jsonl_path=None)`：`log(event_type, **payload)` 统一入口；`log_llm` / `log_tool` / `log_route` 是三个语义化包装（事件类型 `llm_call` / `tool_call` / `route`）。
- 读写都持 `threading.Lock`，`entries` 属性返回列表**拷贝**，避免外部遍历时被并发写破坏。
- 查询接口为评估而生：`since(index)` / `cursor` 取"本轮范围内"的事件（引用校验用），`llm_calls` / `tool_calls` / `total_tokens` / `summary()`（按 purpose 聚合的运行摘要，`main.py` 退出时打印）。
- 关键在于它是**注入**的：`build_client(settings, tracer)` 与 `BaseAgentRuntime.__init__(settings, session_path, tracer, client)` 都接受 tracer，运行时就落 `trace.jsonl`，评估沙箱直接把内存 Tracer 传进去再 `RunTrace.from_tracer(...)` 读出来。

### `main.py`：装配与兜底

- 自己构造 `Settings()`，`--mock` 就地 `settings.mock_mode = True`（改的是本函数局部实例，不碰任何全局）。
- 单轮 `agent.chat()` 抛异常只打印不退出（"单轮失败不清空会话"），退出时 `agent.save()` + `agent.close()` + `agent.tracer.summary()`。

## 知识点与面试考点

- **pydantic-settings 的优先级是什么？** 显式 kwargs > 环境变量/.env > 字段默认值；这让"构造独立配置覆盖个别字段"成为可能。
- **全局单例配置有什么测试风险？** 谁都能 `settings.xxx = ...`，改动跨测试/跨模块泄漏且不还原（参照项目 沙箱的真实缺陷）；可多实例从根上消除。
- **`extra="ignore"` 为什么重要？** `.env` 通常被多个工具共享，多余变量若导致 pydantic 抛 ValidationError，项目就"配错一个无关变量起不来"。
- **离线判为什么集中在 `is_offline` + `build_client`？** 切换逻辑单点维护；如果散在各调用方，mock/真实两条路径迟早不同步。
- **依赖注入比 monkey-patch 好在哪？** 补丁改的是"别人以为没变的东西"，脆弱且要记得还原；注入让采集（Tracer）成为显式参数，测试自然可写。
- **Tracer 为什么要加锁？** 事件来自 LLM 调用、工具执行、路由多条路径，可能并发 append 与读；`entries` 返回拷贝防止迭代期间被改。
- **`trace.jsonl` 的 `ts` 为什么是相对启动时间的秒数？** 单次运行内单调、紧凑、可比；绝对时间戳跨进程时钟反而易误导。

## 与 参照的电商客服教学项目 对照与改进

| 方面 | 参照项目 做法 | 本项目做法与理由 |
| --- | --- | --- |
| 配置形态 | `settings = Settings()` 模块级全局单例，各模块 `from app.config.settings import settings` | Settings 只是类，`main.py` / 测试 / 沙箱各自构造实例；无隐式共享状态 |
| 评估沙箱隔离 | `settings.memory_enabled = False; settings.mcp_enabled = False` **改全局且不还原**（沙箱自己注释承认"agent.__init__ 直接读全局 settings"） | `Sandbox._settings()` 每次 `Settings(**kwargs)` 构造独立配置，跑完不留痕 |
| 轨迹采集 | `_instrument()` monkey-patch `completions.create` / `beta...parse` / `execute_tool` / `router.route`，维护 patches 列表事后还原 | Tracer 注入客户端与工具注册表，沙箱直读 tracer：零补丁、零全局状态 |
| 离线能力 | 无统一判定，无 Mock 客户端 | `is_offline()` + `build_client()` 工厂一处切换，无 Key 全链路可跑 |
| 运行时可观测 | 仅评估时采集 | 每次调用（带 purpose）实时计量，`trace.jsonl` 落盘 + `summary()` 打印 |
| env 容错 | `model_config` 仅 `env_file` | 额外 `extra="ignore"`，多余环境变量不炸 |
